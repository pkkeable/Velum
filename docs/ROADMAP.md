# Roadmap

The public release is a synthetic technical preview. The intended product includes
real, individually approved submissions; that milestone is still open.

## Before real use

1. Independent storage, HTTP, OAuth, worker and recovery review; fix and independently retest findings.
2. Native platform acceptance, including sleep, browser lifecycle and interrupted key operations.
3. Resolve each route's eligibility and sender-account requirements, especially Hunter.
4. A separately authorized single-route pilot, then a decision based on actual receipts
   and verification steps. Apollo is a candidate, not an enabled live route.

## Later, with separate scope approval

- Permitted discovery/observation adapters; no scraping around challenges or hidden endpoints.
- Optional access requests as a distinct purpose, with separate disclosure approval.
- Local due reminders before any recurring external checks; a timer cannot establish permission.
- Anti-rollback design using trustworthy state outside the database, including recovery semantics.
- Persisted unlock throttling only if its threat model justifies the added durable state.
- Broader native/accessibility coverage and a macOS CI lane.
- An end-to-end encrypted hosted companion: proposal only, requiring a separate data-flow,
  recovery, authentication and deployment review. No hosted service is built or approved here.
- Authorized adult family workspaces, distinct authority records and explicit scope.

No package/module rename, universal live switch, telemetry, external AI, unattended
resubmission or additional broker count is required for this preview.
